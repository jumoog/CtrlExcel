# WinCC OA CTRL Extension for Excel

A WinCC OA CTRL extension that adds `.xlsx` file reading and writing capabilities. Files are read with [calamine](https://github.com/tafia/calamine) and written with [rust_xlsxwriter](https://github.com/jmcnamara/rust_xlsxwriter), two Rust libraries that the extension links statically (`rust/`), so the extension is still a single DLL or `.so`.

## CTRL Functions

### `excelGetSheetNames`

```ctrl
dyn_string excelGetSheetNames(string filename)
```

Returns the names of all worksheets in the given `.xlsx` file. Chart sheets are not listed, since they contain no cells to read.

```ctrl
dyn_string sheets = excelGetSheetNames("C:/data/report.xlsx");
// sheets = {"Sheet1", "Sheet2", "Summary"}
```

### `excelReadSheet`

```ctrl
dyn_mapping excelReadSheet(string filename, string sheetName, bool skipHiddenRows = TRUE, bool firstRowIsColumnNames = TRUE, bool skipEmptyRows = TRUE)
```

Reads a sheet and returns each data row as a `mapping`.

- **sheetName** — pass an empty string to read the first worksheet.
- **skipHiddenRows** — optional, defaults to `TRUE`. When `TRUE`, hidden rows are omitted (also with `skipEmptyRows = FALSE`). A hidden first row still supplies the column names.
- **firstRowIsColumnNames** — optional, defaults to `TRUE`. When `TRUE`, the first row supplies the mapping keys as strings. When `FALSE`, keys are 1-based column integers.
- **skipEmptyRows** — optional, defaults to `TRUE`. When `TRUE`, rows without any value (e.g. rows that only carry formatting) are omitted. With `skipHiddenRows = FALSE` and `skipEmptyRows = FALSE`, `rows[i]` is Excel row `i + 1` (or row `i` when `firstRowIsColumnNames = FALSE`), so scripts can report Excel row numbers. Note that this returns every row up to the last one Excel stored, so a single stray formatted cell far down (e.g. row 1048576) makes the result that long.

Header cells become string keys: numbers are written without decimals (`2024`), dates as `YYYY-MM-DD` (plus ` HH:MM:SS` when they have a time part). An empty header cell falls back to its 1-based column number (`int` key). A repeated header gets a suffix (`Value`, `Value_2`, `Value_3`) so no column is overwritten.

Cell values are automatically typed based on the Excel cell type:

- Whole numbers → `int`, or `long` outside the 32-bit range
- Other numbers → `float`. Excel stores every number as a double and does not distinguish integers from decimals, so a whole-number `float` such as `87.0` reads back as `int`, and integers beyond 2^53 (about 9·10^15) lose precision.
- Booleans → `bool`
- Dates/times → `time` with milliseconds (Excel serial converted to WinCC OA time, treated as local time). Dates outside the range of CTRL `time` (before 1970-01-01, e.g. birth dates or the placeholder 1900-01-01, or after 2262) are returned as their Excel serial number (`float`), with a warning in `getLastError()`. Time-only values (serial below 1, e.g. `08:00`) and elapsed-time formats such as `[h]:mm` are returned as numbers (days, as Excel stores them).
- Strings → `string`
- Error cells (e.g. a formula result `#DIV/0!` or `#N/A`) → the error code as `string`, so they are distinguishable from empty cells
- Formula cells without a calculated value (files generated by tools and never saved by Excel) → `""`, with a warning in `getLastError()`; open and save the file in Excel to calculate them.
- Empty cells → `""`

Workbooks using the 1904 date system (old Mac Excel files) are read with their dates converted correctly.

Excel date serials carry no timezone. In the hour repeated when daylight saving time ends, a written time cannot be told apart from the same wall-clock time one hour earlier and may read back one hour off. A time typed into the hour skipped when daylight saving time starts (e.g. 02:30 on that day) does not exist; it is moved to the next valid time, with a warning in `getLastError()`. Every CTRL `time` (1970 to 2262) lies within Excel's date range, so all of them can be written.

Texts are converted between the project's encoding (e.g. ISO-8859-1) and the UTF-8 used in `.xlsx` files, for cell values, sheet names, filenames and error messages. Header or sheet names containing characters the project encoding lacks produce a warning in `getLastError()`; such headers are still kept apart by the duplicate suffix, but such sheet names cannot be passed back to `excelReadSheet`.

```ctrl
// Read the first sheet with default options
dyn_mapping rows = excelReadSheet("C:/data/report.xlsx", "");

// Read a specific sheet, include hidden rows
dyn_mapping rows = excelReadSheet("C:/data/report.xlsx", "Sheet2", FALSE);

// Given an Excel sheet:
//   | Name  | Age | Score |
//   | Alice | 30  | 95.5  |
//   | Bob   | 25  | 87.0  |

// With firstRowIsColumnNames = TRUE (default):
DebugN(rows[1]["Name"]);   // "Alice"  (string)
DebugN(rows[1]["Age"]);    // 30       (int)
DebugN(rows[1]["Score"]);  // 95.5     (float)

// With firstRowIsColumnNames = FALSE:
dyn_mapping rows = excelReadSheet("C:/data/report.xlsx", "", TRUE, FALSE);
DebugN(rows[1][1]);  // "Name"   (string)
DebugN(rows[1][2]);  // "Age"    (string)
DebugN(rows[2][1]);  // "Alice"  (string)
DebugN(rows[2][2]);  // 30       (int)
```

### `excelReadFile`

```ctrl
mapping excelReadFile(string filename, bool skipHiddenRows = TRUE, bool firstRowIsColumnNames = TRUE, bool skipEmptyRows = TRUE)
```

Reads all sheets in the file at once. Returns a `mapping` where keys are sheet names and values are `dyn_mapping` (rows). If two sheet names become the same text in the project encoding, the later one gets a suffix (`_2`) and a warning.

- **skipHiddenRows**, **firstRowIsColumnNames**, **skipEmptyRows** — optional, default `TRUE`, as for `excelReadSheet`.

```ctrl
mapping allSheets = excelReadFile("C:/data/report.xlsx");

// Access sheets by name
DebugN(allSheets["Sheet1"][1]["Name"]);   // first row of Sheet1
DebugN(allSheets["Summary"][1]["Total"]); // first row of Summary sheet
```

### `excelWriteSheet`

```ctrl
bool excelWriteSheet(string filename, string sheetName, dyn_anytype data)
```

Writes a `dyn_anytype` (containing mappings) to a single-sheet `.xlsx` file. The keys of all rows, in order of first appearance, become the column headers; a row without a key gets an empty cell in that column.

- An empty **sheetName** writes `Sheet1`. Sheet names must follow Excel's rules: at most 31 characters, none of `\ / ? * [ ] :`, no leading or trailing apostrophe, not `History`, and unique ignoring case.
- Characters XML cannot store as-is (control characters, carriage return) are written as Excel's `_xHHHH_` escapes, and text that itself looks like an escape (e.g. a part number `AB_x0041_7`) is escaped as well, so texts round-trip exactly. On read, every `_xHHHH_` escape is decoded, as the file format specifies: also the ones other tools write for printable characters, so a file whose cell holds `AB_x0041_7` without that escaping reads as `ABA7`. A text longer than 32767 characters, Excel's cell limit, fails the write. Empty texts are not stored (as in Excel) and read back as `""` like any empty cell, so a row whose values are all empty (or missing) has no cells and reads back only with `skipEmptyRows = FALSE`.
- More than 1048575 data rows or 16384 columns (Excel's sheet size) fail the write. Column widths follow the longest value, capped at Excel's maximum of 255.

```ctrl
dyn_mapping rows;
mapping row1, row2;
row1["Name"] = "Alice";
row1["Age"]  = 30;
row2["Name"] = "Bob";
row2["Age"]  = 25;
dynAppend(rows, row1);
dynAppend(rows, row2);

bool ok = excelWriteSheet("C:/data/output.xlsx", "People", rows);
```

### `excelWriteFile`

```ctrl
bool excelWriteFile(string filename, mapping data)
```

Writes a `mapping` where keys are sheet names and values are `dyn_anytype` (rows of mappings) to a multi-sheet `.xlsx` file. This is the same format returned by `excelReadFile`. An empty mapping writes a workbook with one empty sheet `Sheet1`.

```ctrl
// Read and write back (round-trip)
mapping allSheets = excelReadFile("C:/data/input.xlsx");
bool ok = excelWriteFile("C:/data/output.xlsx", allSheets);

// Build from scratch
dyn_mapping rows;
mapping row;
row["Name"] = "Alice";
dynAppend(rows, row);

mapping data;
data["Sheet1"] = rows;
bool ok = excelWriteFile("C:/data/output.xlsx", data);
```

### Non-blocking variants (`...Async`)

CTRL extension functions run on the CTRL manager's thread, so while the functions above read or write a large file, **every script in that manager stops**. The `...Async` variants do the work on a background thread instead: only the calling script waits, all other scripts of the manager keep running.

```ctrl
int excelGetSheetNamesAsync(string filename, dyn_string &names)
int excelReadSheetAsync(string filename, string sheetName, dyn_mapping &rows, bool skipHiddenRows = TRUE, bool firstRowIsColumnNames = TRUE, bool skipEmptyRows = TRUE)
int excelReadFileAsync(string filename, mapping &sheets, bool skipHiddenRows = TRUE, bool firstRowIsColumnNames = TRUE, bool skipEmptyRows = TRUE)
int excelWriteSheetAsync(string filename, string sheetName, dyn_anytype data, bool &ok)
int excelWriteFileAsync(string filename, mapping data, bool &ok)
```

They behave like the blocking functions, except that the result is delivered through the reference parameter (like `dpGet`). The return value is `0` if the call was accepted and `-1` for invalid arguments; the outcome of the operation is in the reference parameter and in `getLastError()` once the call returns.

```ctrl
dyn_mapping rows;
excelReadSheetAsync("C:/data/big_report.xlsx", "Sheet1", rows);  // other scripts keep running
dyn_errClass err = getLastError();  // right away: any other call (even dynlen) clears it
if (dynlen(err) > 0)
  DebugTN("read failed", err);

bool ok;
excelWriteSheetAsync("C:/data/out.xlsx", "Data", rows, ok);
```

The data passed to the write variants is copied when the call starts, so the script may change its variables while the write runs. For very large data this copy itself briefly pauses the manager (it is still much faster than writing the file).

Async operations run on a small pool of background threads (up to 4 at a time; further calls queue). Operations on the same file are serialised (reads may run together, writes run alone), so parallel scripts never see or produce a half-written file. A blocking function called on a file that an `...Async` call is currently using does not wait (that would freeze the manager): it fails with a "file is busy" error in `getLastError()`. The reference argument is evaluated again when the result arrives, so it may be an element of a shared `dyn` or `mapping`; if that element was removed meanwhile, the result is discarded with an error. Because of this second evaluation, use a plain variable or an index without side effects (not `rows[i++]`, and not an index another script changes while waiting). A call takes at least a few milliseconds more than the blocking variant, since the waiting script is only checked periodically.

### CTRL++ classes (`ExcelWorkbook`, `ExcelSheet`)

`scripts/libs/classes/ExcelWorkbook.ctl` wraps the functions in two classes. Copy it into the project's `scripts/libs/classes/` directory and load it with `#uses "classes/ExcelWorkbook"` (it loads the extension itself).

- **`ExcelWorkbook`** is one `.xlsx` file. `load()` reads all its sheets (in the file's order) and `loadSheet(name)` one sheet into the workbook; `save()` writes the workbook's sheets to the file. `addSheet`, `getSheet`, `hasSheet`, `removeSheet` and `getSheetNames` work on the sheets in memory, `readSheetNames()` lists the sheets in the file. `setReadOptions(skipHiddenRows, firstRowIsColumnNames, skipEmptyRows)` applies to later loads.
- **`ExcelSheet`** is a named sheet in memory: `rowCount`, `getRow` / `setRow` / `appendRow` / `removeRow`, `getValue(row, column)` / `setValue`, `getColumn(column)`, `getColumnNames()` and `findRows(column, value)`. Row indexes are 1-based, like `dyn` indexes; a missing row or column reads as `""`, like an empty cell.
- Each file call keeps the messages of `getLastError()`: `getMessages()`, `hasMessages()`, `getMessageText()`. A call that returns `FALSE` (or `nullptr`) failed and its messages are errors; messages of a successful load are warnings, e.g. for dates outside the range of CTRL `time`.
- The classes call the `...Async` functions, so the other scripts of the manager keep running; `setCallMode(ExcelCallMode::Blocking)` uses the blocking ones instead.

```ctrl
#uses "classes/ExcelWorkbook"

main()
{
  shared_ptr<ExcelWorkbook> book = new ExcelWorkbook("C:/data/report.xlsx");
  if (!book.load())
  {
    DebugTN("load failed", book.getMessageText());
    return;
  }

  shared_ptr<ExcelSheet> people = book.getSheet("People");
  for (int i = 1; i <= people.rowCount(); i++)
    DebugTN(people.getValue(i, "Name"), people.getValue(i, "Age"));

  shared_ptr<ExcelWorkbook> out = new ExcelWorkbook("C:/data/adults.xlsx");
  out.addSheet("Adults").setRows(people.findRows("Adult", TRUE));
  if (!out.save())
    DebugTN("save failed", out.getMessageText());
}
```

Like the functions, `save()` writes columns and sheets in CTRL mapping key order, which is not necessarily the order in which they were added.

## Error handling

Every function clears and then fills the CTRL error list, so failures can be inspected with `getLastError()`. As for every CTRL function, read it immediately after the call: any other function call in between (even `dynlen`) replaces the list.

- Read functions return an empty result on failure (missing file, unknown sheet, corrupt workbook). `excelReadFile` still returns the sheets it could read and reports the ones it could not.
- Write functions return `FALSE` on failure (file open in Excel, invalid sheet name, data that is not a `dyn_mapping` of mappings, text over the cell limit, data larger than a sheet). A failed write never modifies an existing file: the workbook is written to a temporary file next to it, which then replaces the file.

```ctrl
dyn_mapping rows = excelReadSheet("C:/data/report.xlsx", "Sheet1");
dyn_errClass err = getLastError();
if (dynlen(err) > 0)
  DebugTN("excelReadSheet failed", err);
```

## Performance

Reading and writing take time in proportion to the sheet size. Measured inside a CTRL manager on Windows 11 (`excelWriteSheet` and `excelReadSheet`, best of three runs, 10 columns of integers, floats, texts, times and booleans with one distinct text per row), against the earlier versions, which used OpenXLSX:

| Sheet (rows × columns) | OpenXLSX | OpenXLSX, quadratic lookups worked around | Now (calamine / rust_xlsxwriter) |
|---|---:|---:|---:|
| Write 10,000 × 10 | 0.30 s¹ | 0.18 s | 0.08 s |
| Write 100,000 × 10 | 20.6 s¹ | 1.77 s | 0.83 s |
| Read 10,000 × 10 | 0.51 s¹ | 0.10 s | 0.07 s |
| Read 100,000 × 10 | 75 s¹ | 1.12 s | 0.73 s |

¹ OpenXLSX searched all rows for every row it read and all texts for every text it wrote, so the time grew with the square of the sheet size. Measured with a standalone benchmark of the read and write paths, without the conversion from and into CTRL variables, so inside a CTRL manager it took even longer.

Of the 0.73 s for reading 100,000 rows, about 0.2 s is CTRL copying the returned `dyn_mapping` into the script's variable, which every CTRL function result goes through. `excelReadSheetAsync` hands the rows over without that copy and takes 0.54 s; prefer it for large sheets, also because it does not block the CTRL manager.

## Build

### Prerequisites

- WinCC OA 3.20 API (set `API_ROOT` to your WinCC OA `api/` directory)
- [Rust](https://rustup.rs) via rustup: the build runs `cargo` in `rust/`, and rustup installs the toolchain pinned in `rust/rust-toolchain.toml` on first use. cargo downloads the Rust crates (versions locked in `rust/Cargo.lock`).
- CMake 3.15+
- Windows: Visual Studio (uses the `windows` preset)
- Linux: a C++ toolchain + `make` (uses `Unix Makefiles`)

### Configure and build (Windows)

PowerShell:

```powershell
$env:API_ROOT = "C:\Siemens\Automation\WinCC_OA\3.20\api"

cmake --preset windows
cmake --build --preset relwithdebinfo
```

Debug build:

```powershell
cmake --build --preset debug
```

### Configure and build (Linux)

```sh
export API_ROOT=/opt/WinCC_OA/3.20/api

cmake --preset linux-relwithdebinfo
cmake --build --preset linux-relwithdebinfo
```

Debug build:

```sh
cmake --preset linux-debug
cmake --build --preset linux-debug
```

### Install

Copy the built library into your WinCC OA project's `bin/` directory:

- Windows: `build/RelWithDebInfo/CtrlExcelReader.dll` (or `build/Debug/...`)
- Linux: `build-linux-relwithdebinfo/CtrlExcelReader.so` (or `build-linux-debug/...`)

On Windows, the DLL's version information (Properties > Details, or `(Get-Item CtrlExcelReader.dll).VersionInfo`) shows the version and, as `ProductVersion` (e.g. `2.0.0+a5f43da`), the commit it was built from, so you can tell which build a project uses.

Load the extension in every script that uses it (recommended by WinCC OA):

```ctrl
#uses "CtrlExcelReader"
```

Or load it for all scripts of a CTRL manager in the project's config file (`LoadCtrlLibs` is for CTRL script libraries, not extensions):

```text
[ctrl]
ctrlDLL = "CtrlExcelReader"
```

## Tests

- **Rust tests** (`rust/tests/`; run `cargo test` in `rust/`) cover reading and writing files: the fixture, hidden rows, sparse sheets, escapes, the 1904 date system and replacing an existing file.
- **C++ tests** (`tests/ExcelXlsxCoreTest.cxx`) cover the parts that do not need WinCC OA: date conversion, number typing, header texts, sheet-name checks, and the Rust library through its C interface (fixture, write/read round trip, errors). The normal build compiles them too; run them with `ctest --test-dir build -C RelWithDebInfo --output-on-failure` (Linux: `ctest --test-dir build-linux-relwithdebinfo`). They also build without the WinCC OA API:

  ```sh
  cmake -S . -B build-tests -DCTRLEXCEL_BUILD_EXTENSION=OFF
  cmake --build build-tests --config RelWithDebInfo
  ctest --test-dir build-tests -C RelWithDebInfo --output-on-failure
  ```

  GitHub Actions (`.github/workflows/ci.yml`) runs both on Linux and Windows. Dependabot (`.github/dependabot.yml`) proposes weekly updates of the Rust crates, the Rust toolchain and the GitHub Actions; after a crate update, regenerate `THIRD-PARTY-LICENSES.txt` (CI warns while it is out of date).
- **CTRL tests** (`ExcelRoundTripTest.ctl` for the functions, `ExcelWorkbookTest.ctl` for the CTRL++ classes) need a WinCC OA project with the extension in `bin/` and, for `ExcelWorkbookTest.ctl`, the library in `scripts/libs/classes/`. Copy `testdata/CtrlExcelReaderFixture.xlsx` into the project's `data/` directory for the fixture test.

### Build and test on Linux in Docker

`docker/` builds the extension against the WinCC OA API on Debian and runs all tests: the Rust tests, the C++ tests, `ExcelRoundTripTest.ctl` and `ExcelWorkbookTest.ctl`, in a throw-away project with a CTRL manager that does not connect to Data/Event (`WCCOActrl -n`), so no database, PMON or license setup is needed.

1. Build the WinCC OA image with the Dockerfile that comes with the WinCC OA Debian packages (it is not part of this repository):

   ```sh
   docker build -t winccoa321:3.21.7 path/to/WinCCOA-3.21.7-debian.x86_64
   ```

2. Build the build-and-test image on top of it, then run it with the sources mounted at `/src`:

   ```sh
   docker build -t ctrlexcel-build --build-arg BASE_IMAGE=winccoa321:3.21.7 docker
   docker run --rm -v "$PWD:/src:ro" -v ctrlexcel-build:/build -v ctrlexcel-cargo:/home/winccoa/.cargo/registry -v ctrlexcel-rustup:/home/winccoa/.rustup ctrlexcel-build
   ```

   The volume `ctrlexcel-build` keeps the build (`/build/cmake/CtrlExcelReader.so`) and the CTRL test logs (`/build/ExcelRoundTripTest.log`, `/build/ExcelWorkbookTest.log`); `ctrlexcel-cargo` caches the downloaded Rust crates and `ctrlexcel-rustup` the Rust toolchain of `rust/rust-toolchain.toml`, which the container installs on its first run. The container exits with 0 only if everything built without warnings and every test passed. On Windows, use `-v "C:/path/to/CtrlExcel:/src:ro"`.
